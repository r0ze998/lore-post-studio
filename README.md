# Lore Post Studio

ゲームの世界観を守りながら、X 向けの投稿を企画・下書き・確認・書き出し・記録する、自分専用の制作ツールです。
X には接続しません（ログイン・API・自動投稿・予約投稿の実行・スクレイピングはしません）。データはこのコンピューターに保存されます。

- 対象：まず Wylls（設定は未登録の空プロジェクト）。開発・検証用に **架空のサンプル「塩の街道 / Salt Road」** を別プロジェクトとして同梱。
- プロジェクトはデータの保存先から完全に分離されています（`data/projects/<id>/`）。生成・検査は開いているプロジェクトのデータしか読みません。

## Web で使う（Vercel ＋ Supabase）

ブラウザだけで使いたい場合は [docs/DEPLOY.md](docs/DEPLOY.md) の手順でデプロイできます（無料枠で開始可、合言葉ログイン必須）。

## 起動（PC で使う）

```bash
npm install
npm run build
npm start            # http://127.0.0.1:3000 （このコンピューターからのみ）
# 開発時: npm run dev
```

スマホから同じ Wi-Fi で使う場合：

```bash
APP_PASSCODE=好きな合言葉 npm run start:lan   # 0.0.0.0:3000、Basic 認証（ユーザー名 user）
```

`APP_PASSCODE` がないと LAN 起動は拒否します（合言葉は日本語でも可）。合言葉なしの通常起動では localhost 以外の Host からの要求を拒否し、他のサイトからの書き込み要求も拒否します。インターネットへの公開は想定していません。

### 環境変数（すべて任意。`.env.example` 参照）

| 変数 | 用途 |
| --- | --- |
| `DATA_DIR` | データ保存先（既定 `./data`） |
| `STORAGE_BACKEND` | `supabase` で Web 用の保存先（DEPLOY.md 参照）。未設定ならローカルファイル |
| `ANTHROPIC_API_KEY` | Anthropic API を使う場合のみ。サーバー側でだけ読み、画面には出しません |
| `ANTHROPIC_MODEL` | 既定 `claude-opus-5-5` |
| `APP_PASSCODE` | LAN 利用時の Basic 認証 |
| `ENABLE_MOCK_PROVIDER` | テスト用のモック生成器（外部送信なし） |

## 使い方（制作の流れ）

1. **設定（正本）**：承認した世界観・用語・キャラクター・物語上の出来事・語り口・画像の参考・良い/悪い投稿例と、
   現実側の事実（機能の実装状況・根拠のある実績・告知情報・同意のある実在ユーザーの声）を登録します。
   - 各項目に **出典・更新日・状態（確定／提案／廃止）・公開区分（公開可／未公開）** と変更履歴があります。
   - 過去資料は「資料を取り込む」から入れると **すべて「提案」かつ既定で「未公開」** として入ります（確定設定にはならず、外部にも送りません）。
   - 同じ名前の項目は「矛盾候補」として並べて表示し、**どちらを採用するかは人が選びます**（自動統合しません）。
   - 用語には誤表記、確定項目には「矛盾パターン」（この書き方は設定と食い違う）を登録できます。
2. **企画ボード**で投稿を作り、種類（世界の中の物語／選択・駆け引き／開発進捗／テスト募集／画像・動画紹介／連続投稿・続き）、目的、読者、伝えたい事実、使う設定、素材、続き元を選びます。
3. **切り口**を複数提案させるか、自分で書きます。
4. **下書き**：日本語または英語（英語には日本語の意味確認欄）。スレッドは投稿（セグメント）ごとに「世界内の語り／開発者の語り」を切り替えます。世界内の語りで「※」から始まる行は、世界の外の注記（ゲーム名・告知）として扱います。
5. **検査**：指摘ごとに理由・該当箇所・参照した設定と、そのルールの「見逃し得る範囲」を表示します。文ごとの根拠マップで、どこが設定・事実に基づき、どこが創作かを確認できます。
6. **承認／却下**：理由は必須。要修正が残っている場合は、修正するか「理由を付けて確認済み」にしないと承認できません（サーバー側でも検査し直して確かめます）。理由は「学び」として次の生成・検査に使われます。承認後に本文を変えると「確認待ち」に戻り、投稿済みの記録がある投稿は本文を変更できません。
7. **書き出し**：投稿ごとのコピー、テキスト／Markdown、本文＋素材＋代替テキストの zip、画像生成用の指示文。
8. **記録**：実際に投稿した URL・日時・反応（手動）を記録。投稿済みの判定は **手動記録** で、API で確認したものではないと明示しています。物語投稿で確立した出来事は「提案」として正本に戻せます。
9. **振り返り**：種類別の反応率、反応の高い投稿、採用・却下の理由、学びの管理。

予約候補日時はカレンダーに表示されますが、**このツールは投稿しません**（画面にも明記）。

## 文章生成（交換可能）

| 方法 | 外部送信 | 必要なもの |
| --- | --- | --- |
| テンプレート | なし | なし。正本から確実に言えることだけを埋め、創作部分は［穴埋め］で残す（残ると検査で止まる） |
| 手動中継 | このツールからはなし | 自分で選んだチャット（Claude.ai など）にプロンプトを貼り、返ってきた JSON を貼り戻す |
| Anthropic API | あり（従量課金） | `ANTHROPIC_API_KEY`、かつプロジェクト設定で外部送信を許可 |

- Claude.ai の契約で API が無料で使えるとは仮定していません。API は別の従量課金です。
- API 送信前に、**送る設定／送らない設定と理由・送る全文・概算費用（参考値）・保存方針** を表示し、確認した内容のハッシュが一致しないと送信しません。
- 未公開の項目・提案段階の項目（企画で選んでいないもの）・根拠のない実績・同意のない声は既定で送りません。廃止項目は名前だけを「使わない語」として送ります。素材ファイルは送りません。
- 企画メモ・学び・過去の下書きなどの自由文に未公開項目の名前・別名が出てくる場合は伏せ字にして送り、伏せた場所を確認画面に表示します（名前を使わずに未公開の内容を書いた文は判別できません）。
- 「未公開の項目を今回だけ送る」の選択は、その送信が終わるか画面を閉じると解除されます。
- 安全上の理由でモデルが応答を断った場合、Anthropic 側で別モデルに切り替えて再実行することがあり（`fallbacks: "default"`）、その場合は切り替え先の料金になります。確認画面と送信記録に表示します。
- 送信記録（日時・送った項目 ID・使用量・概算費用）はプロジェクト設定で確認できます。
- 新しいモデル接続は `src/lib/server/providers.ts` に追加します（プロンプトは `src/lib/generation/prompt.ts` で共通）。

### モデル未接続時の制約

設定管理・素材庫・企画・テンプレート切り口・テンプレート下書き・手動編集・検査・承認・書き出し・記録・振り返りはすべて使えます。
できないのは「自然な文章の自動作成」で、テンプレートは骨組みと穴埋めまでです（手動中継を使えば、API なしで外部のチャットに書かせることはできます）。

## X の文字数

2026-10 時点の公式ドキュメント（docs.x.com "Counting characters"）に従い、公式の `twitter-text`（v3 設定）で数えています。
上限 280（加重）、日本語など CJK と絵文字は 1 文字 2、URL は長さにかかわらず 23、NFC 正規化。

**未対応（画面にも表示）**：Premium の長文投稿、投票、引用投稿、記事（Articles）、リッチテキスト、予約投稿の実行。プレビューの見た目は近似です。

## 検査の範囲と限界

[docs/CHECKS.md](docs/CHECKS.md) を参照してください。自由文の矛盾検出は語・パターンの照合で、意味を理解していません。指摘がないことは問題がないことの保証になりません。

## データ・バックアップ

- PC 版：`data/projects/<id>/` に JSON と素材ファイル。書き込みは一時ファイル経由（途中で落ちても壊れたファイルを残さない）。
- Web 版：Supabase の Postgres（文書）と非公開の Storage バケット（素材）。同時更新は版番号の照合で検出して再試行します。
- 削除・置き換えたデータは `data/trash/` に退避（自動では消しません）。
- プロジェクト設定 →「プロジェクトを zip で書き出す」でバックアップ。トップ画面から取り込み（既存プロジェクトに混ぜず、新しいプロジェクトとして追加、または同じ ID を置き換え）。

## テスト

```bash
npm test          # 単体テスト（検査エンジン・保存・生成の安全装置・取り込み）
npm run build && npm run e2e   # PC（Chromium 1366x900）とスマホ（Pixel 7 エミュレーション）で通しの E2E
                               # （PC 版の構成と、Web 版と同じ受け渡し方式の構成の両方）
# 実際の PostgreSQL での確認（任意）
PG_TEST_URL=postgres://… npx vitest run tests/unit/store-postgres.test.ts
PG_E2E_URL=postgres://…/空のDB npm run e2e
```

E2E は `.data-e2e/`・`.data-e2e-web/` を使い、`data/` には触れません。

## 構成

```
src/lib/domain      スキーマ（zod）・表示ラベル・照合・矛盾候補・書き出し
src/lib/checks      検査エンジン・ルール一覧と限界・語彙・X 文字数
src/lib/generation  プロンプト・出力の読み取り・テンプレート生成・費用概算
src/lib/server      ローカル保存・提供元（モデル接続）・生成サービス・初期データ
src/app             画面と API（Next.js App Router）
tests/unit, tests/e2e
```
